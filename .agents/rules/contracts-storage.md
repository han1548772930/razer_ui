# 协议、IPC 与持久化边界

- 修改序列化类型前找出真正的 producer、consumer、帧格式、版本协商和历史磁盘读取方。本项目不同边界的契约分别核验，不能把某一种编码的顺序／兼容规则泛化给所有 IPC 或文件。
- 共享协议保持无 GUI、无平台 I/O；报文构造、长度与值域检查、产品／版本分支及响应语义有明确所有者。外部 JSON 在边界转换为领域类型，缺字段、错类型或未识别响应不能默认成功。
- 自有 IPC 校验帧边界、大小、请求关联、会话身份和错误响应。修改契约时同时更新两端及固定字节／独立期望测试；单纯序列化往返不能证明与旧版本或厂商协议兼容。
- 厂商协议的版本、校验和和 ABI 只能按当前原件实现，不因本程序调整内部类型而改变。来源文件的 SHA 用于分析 provenance，不能充当运行时设备兼容门槛。
- 固定协议默认值、用户配置、待提交草稿、已发布服务状态和已确认设备状态分开建模。持久化成功只证明文件状态；设备或服务成功必须有对应真实响应依据。
- 当前设备状态必须来自当前连接的真实读取／确认，并按当前源码的消费者发布到页面与控件。读取失败、未观测、未知值或断开不能回退本地配置／默认值；连接与重连遵循已核实的读取／初始化顺序，不得任意以本地旧值写回。协议未返回的字段保持未观测，不能从档位数量或值推断本地开关。
- 默认值只用于有当前源码／协议依据的首次初始化或用户明确恢复默认，并核实必要写入／确认。缺少本地配置文件或读取失败不是设备未初始化的证据；已确认的设备设置不能被初始默认值覆盖。
- 自有配置维护版本迁移、稳定身份、未知扩展字段和冲突语义。只在当前真实读写链需要时兼容厂商文件，不能为了内部方便复制其存储结构。
- 写盘保留旧有效文件，使用独占暂存文件、完整写入、必要的同步与原子发布；并发写入采用明确的锁／版本冲突策略。取消和失败只清理本任务的暂存文件，不能删除其他任务的结果。
- 切换设备、配置或连接时拒绝迟到读写结果。读取、状态观察、修改、写回、源码规定的确认／读回及后续刷新都必须接通，实际结果进入页面；不能因保留原版配置缓存语义而丢弃读回。保留有依据的乐观编辑，待提交草稿、设备状态和诊断分开，不擅自增加回滚或确认。
- 测试覆盖截断／超长帧、未知值、产品分支、旧代次、取消、冲突和写入失败中实际受影响的路径；期望值来自独立协议或源码证据，不能从被测输出反向生成。
