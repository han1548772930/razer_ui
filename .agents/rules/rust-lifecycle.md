# Rust 类型、状态与生命周期

- 一个领域事实只有一个可变所有者和转移入口。缓存、原子变量和页面快照只能由该入口派生发布，调用方不能通过协调多个写入者维持一致。
- 用具名参数结构、验证后的新类型和枚举表达实际不变量。独立事实保留具名字段；只有组合确实无意义时才合并为枚举，不能丢失“已配置但当前不可用”等需要持久化或显示的状态。
- 未观测、读取失败、未知协议值、断开与合法默认值分别建模。写入专用 sentinel 只在编码边界产生，不渗入读侧或领域类型；保留协议明确允许的未知标志位。
- 复杂循环把事件转移和纯决策归入同一状态对象，决策显式接收逻辑时间，I/O 留在拥有任务的适配层。使用正常事件驱动测试，不能依赖构造无法到达的私有状态。
- 替换会话、连接或请求时，发布结果和清理都比较完整身份：设备／端点、所有者、代次或请求身份。每个所有者从零开始的计数或共享 payload 指针不能单独证明当前身份；旧任务不得覆盖或移除继任者。
- 任务、订阅、取消句柄、焦点、滚动与设备会话由真实生命周期所有者保留。关闭或切换时先停止接收新工作，再按已核实的恢复、取消、等待和释放顺序收尾；不能以设置停止标志代替完成清理。
- 缓存和租约不能延长其借用的会话。复用句柄／租约前，确认依赖 worker、回调和 OS handle 已退出；失败与超时必须保留实际清理状态。
- 仅部分阶段允许持有的资源随阶段所有权移动；确有必要时用消费 `self` 的状态转移限制非法调用，不为单一构造／写入且已有证明的简单对象制造类型层次。
- 原生通知只能提高及时性。通知可能丢失、合并或不可用时，保留有界重查、超时或经过验证的恢复路径；补查结果不能伪装成通知已完整到达。
- 复用工作区依赖与锁定版本。lint 抑制限于必要项并说明当前约束，优先消除违规原因；不能通过扩大 `allow`、改写测试断言或吞错使检查通过。
