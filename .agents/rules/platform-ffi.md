# 平台适配与原生资源

- 生产依赖边界以根目录 `AGENTS.md` 第3节为准：所有范围内业务由独立 Rust 实现，官方 DLL、NODE、EXE、应用、插件和业务服务仅用于静态分析或显式对照。禁止 FFI、COM／RPC、socket、IPC、helper、子进程或启动官方应用代做业务；协议已核实、服务已安装和本地运行均不是例外。
- 系统 API／系统 DLL、系统 COM、系统设置窗口及必要 USB／HID／BLE／驱动访问可作为平台基础设施；本项目 Rust 服务可承载本项目业务。官方 DSP、映射引擎、提权服务或应用不能因为使用系统 COM／进程 API 调用就变成系统基础设施。新增适配器前必须说明最终业务执行者，无法证明属于允许边界时继续核对，不先接入官方后端。
- 替代时同时迁移真实调用者、结果消费者和关闭恢复链，并删除官方加载器、启动器、安装检测、服务代理、CommonDll 定位规则、FFI 表及失效打包依赖。不得只移除入口或改名；功能缺口继续由 Rust 实现闭合。

- 本机检查只证明实际编译的目标与 feature。修改其他平台的 `cfg` 分支时，能静态检查该目标则检查；否则逐项审阅当前声明、调用方、重导出、依赖 feature 与类型宽度，并明确标记未编译。
- 多个函数随平台分化时，使用单一模块选择和薄公共门面；同一功能的各平台实现保持同一契约。只有后端确实共存、测试替身或跨 crate 边界需要时才引入 trait。
- 原生 API 优先使用版本匹配的有类型绑定；缺绑定的声明留在所属平台适配器。核对调用约定、结构布局、对齐、长度类型、编码、返回值、out pointer、错误读取与最低 OS 可用性。
- `unsafe` 限在必要操作，附近说明真实的内存、线程与生命周期前提。不能靠 `Send`／`Sync` 强制标记绕过线程归属或让回调保存临时指针。
- DLL、COM、HID、回调注册和 OS 句柄使用所有权封装；每种资源明确配对的关闭／释放操作与失败语义。线程限制优先由不可跨线程的句柄和所属执行器表达。
- 注销回调和停止 I/O 后，等待在途调用结束，才释放上下文、函数表和动态库。缓存中的函数指针、借用 buffer 或 lease 不能使卸载后的代码继续可达。
- 权限读取、权限请求与打开资源分别建模；请求由真正拥有资源和进程身份的适配器发起。读状态不能隐式弹权限或写设备，不能把平台差异归为同一种权限问题。
- 执行限制仍以根目录 `AGENTS.md` 为准。用户授权的本地 DLL／服务／设备测试须核实实际来源、版本、架构、ABI 与清理，先只读，再以原值记录、恢复和读回验证可恢复写入；加载成功、静态 ABI 核验和模拟 transport 均不能代替真实功能结果。
