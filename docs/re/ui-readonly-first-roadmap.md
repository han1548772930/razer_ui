## DLL 读写边界

- “读取”指通过已确认的接口查询真实设备、配置、能力或服务状态。静态读取 DLL 字节/导出表仅提供证据，不等于运行时查询成功。
- 当前已有 `src/backend/dll.rs`、`runtime.rs`、`runtime_native.rs` 等基础代码，必须先审计当前来源和实际请求链，不重复造接口或沿用过时 ABI。
- 只凭 `Get*` 名称不能认定无副作用；初始化、订阅、释放、线程/回调和内存所有权都要从当前官方封装核实。无法证明的路径保留明确缺口，不自动触发。
- 写回通常是调用 DLL API 修改设备/服务/配置，不是改写 DLL 二进制文件。此类提交、Apply、设备保存/上传和持久化统一后置；原有本地 JSON 草稿保存另行标注，不冒充设备保存。
- 读取失败/服务缺失时保留未知、离线或错误状态；不以产品目录填造已连接设备，不制造读写成功响应。
