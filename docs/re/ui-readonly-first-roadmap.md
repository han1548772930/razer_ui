## 方向修正

此前按单一PID深挖，每份review手工收录完整源码所有者，导致同一代码库的其他产品继续显示未开始、收据与工作区体积膨胀。今后按AGENTS.md第1.3节执行：

1. **建立跨产品代码身份索引**：对第一梯队全部产品当前MW／UI部署的webpack factory按规范化AST哈希，得到“变体 → 产品集合”；原生函数同理按规范化指令去重。
2. **传播已有证明**：已审阅段落按变体身份自动适用到使用相同变体的产品，并回写能力台账；无法匹配的保持原状。
3. **按未审阅变体派工**：工作队列为“能力 × 尚未审阅的变体”，按覆盖产品数与产品梯队排序；每个变体只审一次。
4. **静态闭合即实现**：能力的全部变体只剩实现／运行验收时立即进入Rust与UI接线。
5. **同步削减体积**：输入内容寻址去重、超大review迁移为身份引用、清理 `target` 与 `.work`。

## 分阶段路线

| 阶段 | 工作 | 完成条件 |
| --- | --- | --- |
| 1. 确定范围 | 当前部署、身份索引、能力台账 | 每项能力有产品、版本／固件、传输身份；缺证据项有取证路径 |
| 2. 共享变体逆向 | 发现／身份、传输、配置档、映射／宏、存储、事件与生命周期 | 输入到释放全链有依据，结论按变体传播 |
| 3. 差异变体 | 只审真实差异的产品／固件／传输分支 | 无未解释差异与未知间接调用 |
| 4. 全量验收 | 按台账复核，只补变化输入 | 第一梯队无未归属静态缺口 |
| 5. 独立Rust与接线 | 协议、平台、服务、状态与原版UI | 真实读写与消费者闭环，官方业务DLL生产依赖清除 |
| 6. 分项验证 | 自动化／模拟测试与授权的DLL／设备对照 | 收据完整；受限项保持未验证 |
