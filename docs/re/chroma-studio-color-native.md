# Current Studio Static color editor

`src/features/chroma_studio_color.rs` implements the inline Static editor from current modules 3181, 1698 and 9170. Receipts and declared assets are recorded in `chroma-studio-color-source.json`; the broader control/CSS inventory is in `chroma-studio-properties-source.json`.

The retained `StudioColor` entity owns its four input entities, brightness slider, color-field drag and subscriptions. `set_value(value, window, cx)` synchronizes owner values without sending a change back. `set_enabled(enabled, window, cx)` discards incomplete drafts when disabling. `StudioColorEvent::Changed(Option<u32>)` commits completed input edits, swatch selections and pointer/slider releases to the owner's transient effect parameters. It does not write a Studio layer or device region.

The field uses the source 228×136 horizontal RGB hue gradient and white vertical overlay; brightness is separate. Conversion follows 9170's HSV functions and 1698's 191/255 brightness threshold, including the gray-base special case. The no-color preset stays `None`. HEX input accepts six hex digits; lengths 1–3 repeat to six characters, lengths 4–5 append `f`, and an empty draft resolves to black. RGB strips nondigits, trims leading zeros and clamps each channel to 255. Input focus selects its text; blur/Enter/Escape commit. Text-field keyboard events stop before Studio's tool and duplicate shortcuts.

Eight fixed source swatches are followed by at most eight custom swatches. A dedicated Studio session global retains custom colors across editor instances, allows duplicates, and is observed by each editor. Only custom colors have the delete context command. Stable internal IDs prevent a menu opened before another removal from deleting a different slot. The source per-user storage load/save bridge (4809/8531) is not implemented: custom colors persist only during the current application session and are not represented as saved user storage.

The native eyedropper remains disabled because `showColorPicker` and its sampling/completion events have no live backend. No successful screen sampling is fabricated. GPUI primitives own text editing, slider interaction and context-menu dismissal. The source shape/geometry/colors are supplied by the Studio view; this editor does not reuse the device-product palette or picker.

Resource preparation statically downloads only the current manifest-declared SVG files and produces the source CSS brightness pointer. Formatting and source/resource checks are permitted; application launch, builds and tests were not used to validate rendering. Browser-versus-GPUI raster rounding and the native context-menu presentation still require permitted visual verification when the execution restriction is lifted.
