## Draft and commit behavior

`handleChange` accepts integer strings and the intermediate strings `""` and `"-"`. It stores and immediately sends the raw string when `allowLiveUpdate` is true. It does not clamp or snap live drafts. Module 82508 `changeTimes` keeps this argument unchanged and requests Save availability without validating the repeat count.

The opt-in native `.live_update()` emits `StepperEvent { value: last_committed_value, draft: Some(raw) }`. Numeric commit/step events emit `draft: None`. A live consumer must read `draft`; existing numeric consumers retain their original events unless live mode is explicitly enabled. The event no longer derives `Copy` because it owns its optional draft string.

Blur, Enter and Escape commit; empty/minus-only values become 0 and then clamp to the minimum 1. The integer increment preserves the source's string concatenation before parsing (`"2" + 1` becomes 21); decrement uses numeric coercion. Source wheel guards use coercive range comparisons against the live parent value, while spinner disabled classes use strict equality. The native live wheel path preserves that distinction.

External numeric updates use existing `sync_value(value, min, disabled, window, cx)`. It does not emit an event and does not rewrite the draft when the committed numeric value is unchanged. A different shortcut mapping uses `reset_value` to replace its input draft even if the numeric values match. `set_value` remains private; it writes the input and emits a commit event.

The default and `.in_modes_area()` layouts remain unchanged. The new Macro caller uses `.in_custom_keymapping().live_update()`.
