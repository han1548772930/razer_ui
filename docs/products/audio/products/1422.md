## 底栏、电平与根生命周期

麦克风底栏在 EQ、Effects、Stream Mixer 显示；当前根条件只排除 Lighting 和 Help，完整条件为 `[275078,275228)`。`isMicSetupOpen` 向导是该条件之外的根兄弟；设备未 ready 的 `processing-layout` 也属于独立状态。

当前底栏 `[189986,193834)` 从 `micReducer` 读取采样率、音量、ready、实时预览开关与 `levelMeter`。产品配置将 Microphone 映射为 `DeviceId_MarieMic`；找不到相应条目时才尝试 `DeviceId_Microphone`。存在非空 meter 数组时取首值并夹到 `0..100`；条目或数组缺失传 `undefined`。非空数组首值为 null／undefined 时原版以 0 呈现，此 UI 回退不能标为设备实测 0。

底栏将上述值传入完整波形 hook `[180236,189953)`。正数且为 number 的外部百分比映射为 `percent / 100 * 60 - 60` dB；零值、缺失或无效外部值进入浏览器 analyser RMS 分支。它们是两种真实显示来源，不能混写成设备读回或 DSP 成功。预览还要求浏览器音频准备、设备 ready、窗口／标签 active、文档 visible 和预览开关满足；采样率选项来自产品配置的 `48000/96000`。

hook 保留 generation 检查、迟到 stream 的 stop-tracks、retry／interval／animation frame 取消、节点 disconnect、tracks 停止、AudioContext 关闭及缓存释放。根监听的生命周期另行记录：

| `componentDidMount` | `[268877,271707)` | 载入本地 profile 与 Stream Mixer；注册设备变化、beforeunload、MW channel 与 window message；对 ready 和 mixer-enable 消息分发实际 reducer 动作 |

## 当前驱动配置、注册与关闭

统一音频收据的 `driver_lifecycle` 接续 `endpoint_local_chain` 与 `seiren_native_dsp`，只复核当前原件，不重跑端点／DSP 捕获。当前 [Host 4.0.896](../../../../.analysis/inputs/host-current/releases/4.0.896/acquisition.json) preload 声明 `supportElectron20=true`；AudioMarie 据此进入 `80995.oE → apiElectron.doDLLMainActionAsync → ffiPreloadAsync → FFIPreloadMain.callDLLAsync`。原版保留的旧 `80995.I3` 分支调用 `doDLLAction`，当前 preload 只记录 deprecated。AudioMarie 在 `ConfigureFFI` 后先置 `isInit=true`，依次查询 DLL 版本、注册事件、调用 `DeviceInitialize`，没有用设备初始化结果重置 `isInit`。Host channel mutex 只覆盖所等待的导出调用，不能证明 DLL 自己的异步任务结束。

当前驱动包的 [custom.ini](../../../../.analysis/inputs/official-native-current/extracted/b865d116e4260cc895f68dd6013dd653ce4625982dd0dd816aac2f66b1fad8ce/custom.ini) 与 INF 使用相同 InterfaceGUID `{D132049C-EE3B-4647-AC9E-E754FA90FD46}`。[安装任务 XML](../../../../.analysis/inputs/official-native-current/extracted/b865d116e4260cc895f68dd6013dd653ce4625982dd0dd816aac2f66b1fad8ce/tlsetupfx_drv.xml) 在安装驱动前登记 API／ASIO 的 x86、x64 DLL；安装准备、卸载与更新卸载先注销同一文件集。本次只读取这些声明，没有运行安装器或注册导出。

包内 x64 API 的 `DllRegisterServer` 从模块旁 `custom.ini` 解析 DriverInterface／InterfaceGUID，把模块实际路径以 REG_SZ 写入 `HKCR/CLSID/<GUID>/InprocServer32`；注销递归移除该 CLSID，目标不存在可成功返回。Marie 从当前进程注册表视图读取该默认值，接受 REG_SZ／REG_EXPAND_SZ，但未展开环境变量便传给 `LoadLibraryW`。它请求 `CheckApiVersion(5,14)`；当前包返回版本 `5.15`，检查实际为 `major==5 && unsigned minor<=15`，因此静态兼容，并非要求版本等值。后续打开驱动 API 的 index 0，没有按本页 container 匹配 API 设备。本机实际注册表内容、注册路径及最终加载模块都未观测，包内版本不能证明已经加载了该 DLL。

关闭链存在独立的异步边界：`DeviceTerminate` 查到容器后仅尝试把移除任务加入全局队列，忽略提交结果并返回 true，没有等待容器移除。实际任务按不区分大小写的 container 匹配释放引用；CCamyDevice 析构通知 meter 线程停止，只等待 1000 ms，超时仍关闭线程句柄并继续释放。随后关闭 driver device、卸载 API DLL、清函数表；API close 检查槽位与完整 handle，释放 I/O handle，设备析构释放事件 handle。页面注销监听、Host 的 `FreeFFI` 成功返回，以及原生的局部关闭，都不能证明全部队列、设备通知和 FFI callback 已静止；取消／重连及这些在途分支仍待接续，整产品与实际 DLL／设备对照保持未完成。
