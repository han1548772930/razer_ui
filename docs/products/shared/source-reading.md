# 源码阅读与功能文档的对应方式

本目录解释官方源码实际实现的产品、页面和功能。产品文档说明该型号挂载了什么；功能文档解释用户操作的目的、数据来源、计算、服务调用和生命周期。文档中的函数名称与参数保留原件拼写，不用本项目的实现替代官方行为。

## 产品、页面和功能是三层对象

产品使用 PID 定位；edition、layout、连接方式和配件状态继续决定产品内部的分支。页签名称不是能力开关：同名页面可能挂载不同组件，同一组件也可能因调用者传入的参数而隐藏部分功能。

逐产品文件的“页面构造”保留真实 JSX 调用。例如传入 `supportSharpness:false` 的图像页，与没有该参数的通用图像组件不是同一功能集合。文档中的数组顺序来自当前原件，不能用名称重新排序来推定原版顺序。

下拉框、抽屉、帮助、校准向导、错误提示、独立窗口及设备事件属于功能链的一部分。页面入口被找到后，还要继续查看其组件、事件处理函数、reducer、任务工厂、中间件、服务／设备命令、结果消费者和退出路径。

## 如何回查证据

字节区间均为原始 UTF-8 文件的半开区间 `[start,end)`，不是编辑器行号或 JavaScript 字符下标。原件在 `.analysis/inputs/`，获取来源、版本、字节长度和 SHA-256 在对应获取收据中；完整函数、交叉引用和未解边在 `.analysis/results/` 的既有捕获中。

当前 HTML 实际包含的脚本、manifest 声明的候选分块、lazy loader 指向的分块和仅因历史获取而保留的旧文件是不同集合。候选文件包含一个组件，不能单独证明当前页面挂载了它。逐产品结构读取只把当前声明原件中的描述符作为描述符记录，动态挂载关系另沿调用者核对。

官方没有发布可取的 source map 时，继续从发布 JS 恢复完整模块、词法参数绑定和回溯原件的合成映射；不能仅登记缺失后停止。恢复目录及核验方式见 [静态工具说明](../../re/tooling.md)。合成映射帮助定位现有代码，不冒充已经丢失的官方原始变量名称或注释。

产品登记表用于保证检查范围覆盖全部登记产品。历史导航定位和旧 source 字段不构成当前源码证据。逐产品文件重新读取当前原件，解析真实名称导出、数组、组件参数和组件本体；不能用旧目录直接生成结论。

## 读懂一个操作所需的内容

| 问题 | 文档应给出的源码事实 |
| --- | --- |
| 用户正在操作什么 | 真实页面、对象、选中身份与适用产品分支 |
| 当前显示从哪里来 | 本机文档、设备 GET、服务查询、共享窗口状态或组件临时值的具体 producer |
| 输入是什么意思 | 单位、范围、步长、解析、键盘／鼠标行为、禁用条件与转换公式 |
| 操作触发什么 | 调用参数、reducer、任务类型、调度与取消顺序 |
| 改到哪里 | 本机文件、IndexedDB、进程服务、映射引擎、驱动、HID 或系统集成的具体 consumer |
| 怎样知道结束 | 原版实际使用的应答、读回、事件、广播或保存回调 |
| 错误和离开时发生什么 | 实际 catch、取消分支、监听注销、恢复调用和资源释放；源码没有的步骤不补写 |

源码本身若存在不同 producer 的字段不一致、不可达转换或没有被消费者执行的命令描述符，文档保留这个事实。发现问题与改变产品行为是两个任务；此处只进行逆向理解。

## 每个页面都要单独核对

页面核对覆盖设备页、宿主页、独立窗口及其全部嵌套界面。先从当前 HTML 和实际 lazy loader 追到挂载根，再保留产品、edition、固件、连接、配件和窗口策略的条件；同族样例或找到导航数组不能代替其余分支。

| 核对维度 | 需要保留的事实及 Rust 对应项 |
| --- | --- |
| 页面树和入口 | 实际导航顺序、父子组件、页签、面板、抽屉、弹窗、菜单、tooltip、向导、独立窗口与出现条件；对应生产入口，区分预览和真实挂载 |
| 视觉和资源 | 原始 JS props 与 CSS 的尺寸、布局、边距、字体、颜色、图标、图片选择、层级、滚动区域、缩放和换行断点；逐项对应产品主题、目录资源和实际渲染所有者 |
| 文案和身份 | 各语言键、插值、禁用原因及错误文案；列表、选择、焦点和持久化使用稳定领域身份，不能以译文或列表下标替代 |
| 交互状态 | 正常、hover、按下、选中、禁用、加载、空、失败、断开及未知值；每个输入、按钮、拖动、快捷键和鼠标／键盘路径的真实处理函数 |
| 弹层与焦点 | 打开触发、默认焦点、Tab 顺序、Enter／Escape、外部点击、嵌套层关闭、取消、焦点恢复和打开后设备切换 |
| 生命周期 | 挂载读取、初始化、订阅、迟到结果、切换、重连、休眠、关闭、取消、恢复、监听注销、worker 退出及资源释放 |
| 动作结果 | 从页面参数逐层追到实际读写、应答／读回、事件消费者、页面刷新和持久化；Apply／Save／Cancel 的实际含义分别核对 |

每项记录官方证据、Rust 所有者、调用方、实际测试和未执行验收。Rust 已有布局但按钮固定禁用、数据为空、只操作样例或只显示服务未连接，均属于尚未接通的具体缺项；不能计为页面完成。反之，某项纯逻辑测试通过也只证明该状态或算法，不能自动证明页面的尺寸、资源、焦点和设备链。

静态扫描完整 JSX 所有者、处理函数和条件上下文使用 `audit-ui-tree`，收据为 `.analysis/results/frontend/ui-tree-audit.json`；它保留解析失败、缺失原件和未建立的挂载关系。实际阅读和差异写回对应产品／功能文档，未决项归入统一 gaps。主应用窗口和像素运行验收受执行规则限制，未执行时明确保留未验证。

## 从 native 导出读到实际设备操作

原生链至少区分导出包装器、container/实例查找、产品工厂、虚表实际目标、系统接口或设备协议及结果消费者。导出名称不是设备能力声明，包装器清零的输出不是设备读回。需要从原件表字节核实所有间接目标，并继续读入参转换、命令顺序、应答条件、持久化和恢复/释放。系统接口的间接槽还要结合 IID、实际寄存器与栈参数核实 ABI，不能照抄反编译器的暂定签名。

[摄像头原生链](../accessories/camera.md#genericcamera-原件版本与虚表)给出一个具体例子：相邻版本加入两个虚方法后，后续槽整体偏移 `0x10`，恢复命令的参数也有实际变化；共享导出仍会在某些型号落到无设备 I/O 的返回 0 函数。`StartCamera` 的实际函数只检查实例是否存在，不能凭名字宣称开始媒体捕获。读取失败后仍序列化清零临时值的行为则需要同时保留原始返回与失败证据，不能把它转为 Rust 已确认状态。

追加捕获只分析经核实的私有副本。每个 supplement 记录原件身份、Image Base、表位置/字节/哈希、RVA、完整函数、类型依据和 session；基准捕获与数据库是否保持不变也要核验。修复反编译失败必须有完整原汇编的参数或函数边界依据，并保留原失败与追加结果。摄像头 UTF 辅助函数的类型恢复只消除该函数的反编译缺口，不表示摄像头业务链、DLL 对照或 Rust 实现已经完成。

## 独立 Rust 实现与原版对照

文档中的报文、计算和状态转换是独立实现的依据，生产路径不通过官方业务 DLL 完成功能。全功能及产品、固件、传输、平台分支的测试规则见 [验证规范](../../../.agents/rules/verification.md)。无设备时先测试纯计算、模拟传输、错误/取消/重连和有来源的应答回放；测试的期望来自已核实的原件事实，不能让本地实现自己生成“正确答案”。

实际 DLL 对照必须经过独立显式入口，逐项保留官方实际执行的调用、输入、输出、状态变化、应答/读回、差异和释放证据。先核对只读功能；可恢复写入须记录原值、写入、读回并恢复原值，禁止以执行入口、加载成功、双方均未连接或模拟一致作为功能通过。受设备、执行授权或证据不足影响而未执行的分支，继续记录“未验证”。

## 阅读完成与捕获完成

静态捕获能够证明原件身份和保留了完整函数，不能自动证明函数语义已经理解；导航抽取能够证明描述符和组件位置，不能自动证明整页和所有原生调用已经闭合。相关边界在各功能文档中具体写出，未查明的调用继续沿当前原件追踪。

源码获取、逆向语义、Rust 独立实现、UI/后端接线、静态/模拟验证和运行时验收分别核对。校验完整函数文件的哈希、恢复一处反编译错误、静态表覆盖或单个纯测试通过，只能提升其对应项的证据，不能合并成整个产品已完成。
